# AE Auto Patterns / AE 自动样板

独立的 AE2 附属，模组 ID：`aeautopatterns`。不修改 AE 本体。自动样板终端连接 ME 网络后，根据目标物品递归规划工作台、切石机及锻造台配方，消耗空白样板，生成 AE 原生编码样板。

## 安装

- Minecraft **1.21.1**、Java **21**、NeoForge **21.1.169 或兼容的更高 21.1 版本**。
- AE2 **19.2.13**（本项目实际构建、测试版本），以及 AE2 要求的 GuideME；开发环境使用 GuideME **21.1.1**。
- 将 `build/libs/aeautopatterns-1.0.0.jar` 放入客户端和服务端的 `mods` 文件夹。
- 不兼容 Fabric / Forge 版本；当前声明的 AE2 兼容范围是 `[19.2.13,19.3)`。
- Java 源码采用 LGPL-3.0-or-later。第三方依赖与上游来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)；可选联动模组不会成为硬依赖。

## 操作

游戏内说明已接入 AE 的 GuideME 指南：**准星对准已安装的自动样板终端，按 G** 查看使用方法、常见问题和简要原理。世界中的快捷键可在“控制 → AE 自动样板 → 查看终端说明”中修改；背包中悬停终端物品时，按住 GuideME 的查看指南键（默认 G）也可打开。页面同时收录于 AE 指南的设备分类，提供中文和英文，跟随游戏语言切换。

多配方选择：同一材料具有多个工作台、切石机或锻造台配方 ID 时，分析会将该分支标为“待选择配方”，继续分析其他独立分支。点击标记材料即可打开 3×3 配方预览，用左右箭头翻页，点击“确认配方”应用路线并重新分析；取消保留待选状态。所有待选材料确认或手动设为外部供应后，才允许开始编码。标签原料候选不算多个配方，处理配方不触发这一选择步骤；网络或输出栏已有样板仍优先复用。已确认的循环路线会报告问题，不会静默改为外部供应。选择随终端保存，重载后重新分析时检查有效性。

分析采用增量候选图、循环分组和可行性传播；修改路线时只重新分析受影响的材料。服务端以共享时间预算分步执行，JEI 只提供候选排序建议，不作为配方数据来源。

1. 合成或使用 `/give @s aeautopatterns:auto_pattern_terminal` 获取终端 Part；对 ME 线缆侧面使用它来安装。
2. 放置终端，通过 ME 线缆接入有供电、可用频道的网络。终端占用一个频道，待机耗电 1 AE/t。
3. 右键打开。搜索物品名称或注册 ID，点击结果选择目标；列表显示四行，可用滚轮浏览全部搜索结果，输入完整 ID 可以精确缩小范围。安装 JEI 时，也可将 JEI 列表中的虚拟物品拖到目标列表区域作为分析目标，无需实际持有；服务端按物品及组件重新分析。也可在光标上拿起物品，点击“选取光标物品”，保留数据组件且不消耗物品。

右上方路线标题旁的“忽略组件”默认关闭。勾选后，光标目标按该物品默认实例分析，忽略已充能、磨损、自定义名称等额外组件，不修改光标中的实物。已有光标目标会自动重新分析；关闭后恢复原始光标目标组件。开关及原始光标目标随终端保存。此选项只影响目标选择，不放宽配方原料、网络样板或编码校验；特定盔甲纹饰等需要组件才能区分的目标应关闭该选项。

4. 点击“分析”。左侧查看依赖，点击节点选中，点击 `+ / −` 展开、折叠；在列表区域滚动鼠标滚轮逐行浏览。右侧切换配方，使用原料左右箭头选择原料槽，再点击“切换原料”更改标签候选。点击“切换外部供应”设置或取消手动终止节点。修改会重新分析。
5. 汇总依次显示：待生成 / 网络已有 / 输出栏已有 / 外部供应 / 不支持。待生成数量就是本次所需空白样板数。
6. 将 AE 空白样板放入中间输入槽，点击“开始/继续”。每 tick 最多编码一张，生成结果进入左下方 27 格缓冲区。Shift 点击可转移物品。
7. 取出编码样板，手动装入样板供应器，配置分子装配室或机器并供应基础原料。

主界面大小为 386×270 GUI 单位。左侧独立“待处理材料”栏同时列出待选配方和当前未解决路径的阻塞材料，不受依赖列表折叠影响；用状态文字区分两类。点击待选项直接打开 3×3 配方预览；点击未解决项定位到依赖列表中的阻塞材料，悬停可查看完整失败路径和配方 ID。每项前的复选框支持多选；顶部“全选/清除”作用于整份待处理清单（含滚动区域外的条目），点击“外部供应”把勾选材料一次性设为手动外部供应并重新分析。勾选可跨滚动保留，任务修订后清空，选择属于当前玩家界面，外部供应设置属于共享终端任务。滚轮浏览，最多显示 8 项。侧栏宽 72–112 GUI 单位，与主面板间隔 6；缩放后的窗口宽度不足 476 时，改为点击依赖区标题位置的“待选/未解决：数量”切换至三行清单，顶部仍保留批量按钮，再点击“配方树/依赖”标题按钮返回依赖列表。若主界面自身裁切，请降低 GUI 缩放或放大游戏窗口。

分析完成后，可点击依赖区标题右侧的“依赖树”打开半透明树图，原终端界面暂时隐藏。目标材料是唯一顶层节点，同一深度严格对齐，层间距为 86 GUI 单位；父节点居中于首尾子节点之间，以竖线、水平分支线和竖线连接。同一父节点下重复材料合并，不同父节点下的共享材料分别显示并继续展开各自子树，样板编码仍按材料去重。完整布局预先计算，服务端每 3 tick 最多显示 128 个新节点，加载时位置不变。最多展示 4096 个节点（含重复分支），达到限制时标记未展开分支，并在底部提示。拖动空白区域平移，滚轮以鼠标为中心缩放，“重置视角”对准顶层目标。点击材料查看状态、库存、配方和原料；右侧可切换配方、外部供应和原料候选。任意一个共享材料的微调会同步影响所有对应分支，并自动重新分析，清除旧图后按同样节奏显示新路线。按 Esc 或“返回终端”回到原界面，任务与库存保留。

树图左侧提供紧凑材料清单，随节点分批加载更新。同一种材料只列一次，可按名称或物品 ID 搜索；鼠标悬停清单时使用滚轮浏览，点击条目会将对应材料的首次显示节点居中，并同步选中、读取右侧详情。树图区域内滚轮仍用于缩放，微调后清单随新路线重新生成。

"选取光标物品"旁新增“处理样板”勾选开关，默认关闭，设置随终端保存。开启后，标准熔炉、高炉、烟熏炉和营火配方加入递归候选，生成 AE 处理样板；关闭时不生成新的处理样板，但仍可复用网络或输出栏已有的样板。切换会重新分析并停止旧执行队列，保留已经生成的结果。每张新处理样板消耗一个空白样板，悬停说明中附带青色高亮的完整配方 ID；工作台、锻造台、切石机仍生成各自原生样板。处理样板需配合相应机器、输入输出管道使用，燃料及能量另行供应。其他模组配方需由内置适配器稳定解析；未知动态结果、概率产物约束和特殊机器条件不会被伪装成 AE 样板约束。

### 通用机器适配接口

`integration` 提供统一的 `AdaptedRecipe`、`StackSpec`、`ChanceOutput` 和 `MachineRequirements` 模型。输入输出均使用 AE `GenericStack`，因此可同时表达物品、流体、精确数量、多确定输出、催化剂/容器/返还物和机器条件。`GenericProcessingAdapter` 会生成一张包含全部确定输出的 AE 处理样板；概率副产物不写入确定输出，只进入样板 Lore 和终端详情。无法可靠解析的动态配方保持为“不支持”。

第三方机器通过 `RecipeAdapterProvider` 使用 Java `ServiceLoader` 注册，声明 `adapterId`、优先级并返回适配器。适配器负责索引、候选解析、验证、编码和说明；`AdapterRegistry` 负责与内置适配器组合，单个外部适配器异常不会阻断其他路线。机器燃料、能量、温度、压力和等级只作为条件提示，需玩家在网络外配置。

第三方模组应在 `neoforge.mods.toml` 中将 `aeautopatterns` 声明为可选依赖，并使用 `compileOnly` 引用本模组 API；未安装本模组时不得直接加载适配器实现类。

适配器还可提供能力声明（物品/流体、多输入、多输出、概率、催化剂等），终端只展示服务端解析结果。数据包可在 `data/<namespace>/aeautopatterns/adapter/*.json` 声明机器类型、配方类型和字段路径；声明本身不会猜测配方，复杂配方仍须 Java `RecipeAdapterProvider`。示例见 `data/aeautopatterns/adapter/example_machine.json`。

当前随包提供六个无硬依赖的可选桥接：Mekanism、Create、Thermal、Immersive Engineering、PneumaticCraft、Modern Industrialization。其余五个桥接只在目标模组已加载且配方能稳定暴露普通 `Ingredient` 与 `ItemStack` 时启用；复杂流体、多概率输出和特殊机器条件保留给专用适配器，不会被反射猜测。Mekanism 化学品支线见下文。

Mekanism 化学配方采用独立的 Applied Mekanistics 支线：只有 `mekanism` 与 `appmek` 同时加载才启用，使用 Applied Mekanistics 注册的 `MekanismKey`，因此它未安装时不会影响终端。该支线读取 Mekanism 的公开化学配方 Ingredient/representation/output-definition API，可覆盖化学品到化学品、物品到化学品、化学品到物品、流体+化学品和 pressurized reaction 等含化学输入或输出的确定配方；Mekanism 气体由其 Chemical API 统一表示。AE 样板编码为处理样板，化学种类和数量保留在 AE Key/GenericStack 中。不能从公开定义确定的动态/概率结果仍不会猜测。源码依据：[Applied Mekanistics 1.21.1](https://github.com/AppliedEnergistics/Applied-Mekanistics/tree/dev/1.21.1) 的 `MekanismKey` / `MekanismKeyType` 和 Mekanism 1.21 API 的 `ChemicalStackIngredient` 与化学配方类型。

终端的工作台合成配方：

```text
铁锭       玻璃       铁锭
运算处理器 工程处理器 运算处理器
铁锭       福鲁伊克斯水晶 铁锭
```

## 递归规则

- 工作台有序、无序、标准切石机及锻造升级配方来自服务端 RecipeManager；按配方 ID 稳定选择，遇循环回溯尝试其他配方或原料。切石机和锻造台使用 AE 原生对应样板，和工作台样板一样可交给样板供应器及分子装配室使用，不需要摆放实际切石机或锻造台。
- 支持原版盔甲纹饰：拿起带有所需纹饰的目标物品，使用“选取光标物品”保留具体数据组件。根据目标纹饰、材质和底材反查标准纹饰配方，实际组装和 AE 解码均验证精确输出。搜索列表中的普通盔甲不代表某个具体纹饰目标。
- 精确匹配物品及数据组件。优先复用网络已注册的可用样板，然后复用本终端输出栏中的有效样板；普通存储里的样板物品不算已部署。
- 已有样板仍继续分析输入。例如 A 需要 B、B 需要 D，即使 A 或 B 已有样板，仍补全缺失的下游样板。
- 共享依赖去重，按依赖优先顺序生成；每张消耗一个空白样板，不消耗配方原料。网络现有材料库存只展示，不会终止递归。
- 循环处理不依赖物品名称或模组 ID：对其他模组的标准有序、无序工作台配方同样生效。标签候选先排除当前上游依赖，按路线局部剪枝，不会将某条路径中的循环结果缓存为全局不可用。玩家锁定的循环路线不会被静默改写；无解时需更换路线或指定外部供应。
- 矿物块、矿物、粒等互转配方发现循环时，跳过无法改变失败原料的后续替代组合，并缓存同次分析的候选查询；有无环路线则继续尝试，无解时显示循环路径，由玩家换配方或设置外部供应。
- 可以读取已有加工样板的输入，并生成其输入涉及的上述原生样板；勾选处理样板时也可生成受支持的标准烹饪处理样板。未被可用配方适配器解析的流体或机器输入作为外部供应显示；已支持的化学品输入由 Applied Mekanistics 支线提供。
- 工作台配方按能力识别，不使用模组/物品白名单：支持 `ShapedRecipe`、`ShapelessRecipe` 的模组子类，以及提供可枚举原料、可用默认九宫格排布匹配的 `CraftingRecipe` 包装实现。NeoForge 自定义 Ingredient 提供的物品组件会保留，并用其自身 `test` 校验。适用于常见的机器升级、耐久/组件继承配方；是否可生成仍以所选具体输入的真实输出和 AE 解码验证为准。
- 能量、耐久和其他数据组件仍精确匹配，不能把充能物品当作空能物品。不会从目标组件反向猜测输入组件：非默认组件目标必须有可枚举、实际能够生成该目标的原料。已知产物但无法解析或组件不匹配的目标标记不支持；无法声明任何产物的动态配方无法建立索引。需要特殊布局、隐藏原料或不确定输出的配方仍需专用适配器。单张配方索引异常记录配方 ID 和类名，不阻断其他工作台配方。
- 编码前验证实际配方匹配、组装输出和 AE 解码。右上角路线标题旁复用 AE 原版“物品替换”和“流体替换”图标按钮及提示；默认物品替换关闭、流体替换开启，与 AE 样板终端相同。物品开关应用于新生成的工作台、切石机和锻造台样板，流体开关应用于工作台样板；处理样板不受影响。悬停已开启的流体开关时，当前所选配方可被 AE 替换为流体的材料行及当前原料显示绿色（依赖路线仍显示选定的容器物品）。设置按终端保存，切换会重新分析，保留并继续复用已有样板。工作台配方原有的容器返还行为由 AE 保留。

## 暂停和恢复

- 空白不足、输出满、网络离线会等待；条件恢复后继续。手动暂停需点击“开始/继续”。
- 网络拓扑、所选已有样板、数据包发生变化时，要求重新分析。断电但拓扑未变化可自动恢复；拆线引起拓扑变化需重新分析。
- 保存输入输出库存、目标、路线选择及进度。区块重新加载后要求重新分析，输出栏样板参与去重，保留已生成成果。
- 取消终止分析或执行，保留库存。一个终端的任务由所有玩家共享。
- 分步分析默认限制 512 层、16384 个候选材料、262144 条候选边及 262144 次搜索尝试；树图显示仍最多 4096 个节点。超限时缩小目标、指定路线或设置外部供应节点。容量可在服务端配置中修改。

“完成”表示选定路线所需样板已生成；实际自动合成还需要安装样板、配置供应器及机器、供应基础原料。

## 分析配置与诊断

服务端世界的 `serverconfig/aeautopatterns-server.toml` 首次加载时生成：

```toml
[analysis]
maxDepth = 512
maxMaterials = 16384
maxCandidateEdges = 262144
maxSearchAttempts = 262144
globalMillisecondsPerTick = 4.0
sessionMillisecondsPerTick = 2.0
```

这些是分析容量和软时间预算，不改变样板编码或材料数量。增大容量会增加内存和完成耗时。配方树的 4096 显示上限与分析容量独立。悬停状态行可查看阶段、候选材料/边、搜索、缓存、复用、计算用时、JEI 等待数及适配器异常/慢调用。日志 `aeautopatterns.analysis` 记录完成统计，`aeautopatterns.analysis.adapters` 报告首次超过 4ms 的调用及集成异常。

JEI 仅为服务端已验证配方提供推荐顺序。每批 32 个键、最多两批在途，40 个服务端 tick 未响应则本次分析回退到服务端候选；关闭界面、取消或重分析后旧回复失效。客户端每 tick 最多处理 2 个键，并在键边界检查 1ms 预算。客户端和服务端均须更新本模组（网络协议版本 3）。

## 构建与验证

### 供应器管理与自动续接

点击终端的“目标供应器”进入独立管理页。搜索名称、物品 ID 或坐标；每页两列三行卡片显示供应器模型、空位和上传顺序。左侧复选框用于多选，点击卡片打开详情，可“仅选此供应器”或设置“仅存入合成样板”。返回后开启终端的自动上传功能。

上传按勾选顺序进行。开启顶部“空间不足自动续接”后，当前供应器满时，可续接已选且勾选“仅存入合成样板”的后续供应器。合成类包含工作台、切石和锻造；处理样板不会进入仅合成供应器。未选设备不会自动接收。全部满时暂停且不扣空白，腾出空间后继续；此限制仅约束本终端的上传，不拦截玩家或其他设备。选择顺序、类型限制和总开关随终端保存，客户端与服务端需同时更新。

使用 Java 21，在本工程目录执行：

```powershell
.\gradlew.bat build
.\gradlew.bat runGameTestServer
.\gradlew.bat runClient
```

构建结果位于 `build/libs/`。`src/gameTest` 和 `src/test` 不包含在发布 JAR 中。

代码按 `part`、`client`、`menu`、`network`、`logic`、`integration` 划分。`integration/RecipeAdapter` 是后续机器配方适配入口；当前适配器覆盖工作台、标准切石机、锻造升级及按具体目标匹配的盔甲纹饰。其他模组的配方子类和可解析工作台包装实现可参与递归，特殊机器和隐藏/动态原料仍需适配。DGmodules 仅作目录组织参考，未复用实现。

终端采用 AE Part 风格的 `display_base` 外框和独立面板状态层；安装在 ME 线缆侧面后沿用 AE 的频道、供电、拆卸和朝向逻辑。面板亮度层使用 AE CableBus 的 tint index，因此会随对应颜色线缆显示颜色。
